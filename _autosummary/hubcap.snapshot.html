hubcap.snapshot#

Incremental snapshot of GitHub orgs: issues, PRs and discussions with all comments.

snapshot_github(["my-org"], store=...) writes, per item, a markdown file with front matter, plus index.jsonl (one line per item) and raw.jsonl (the API payloads). Re-runs are cheap: a per-repo updated_at high-water mark is kept in a state store and only newer items are fetched.

Three seams, each one keyword argument:

  • client: where the data comes from (default GithubClient, REST + GraphQL via requests). Anything with the same four methods works, which is also how the tests run offline.

  • store: where files go, any MutableMapping[str, str] (default: a folder, via dol.TextFiles).

  • render: (kind, repo, item) -> str, the markdown strategy.

>>> render_markdown('issues', 'o/r', {'number': 1, 'title': 'T', 'body': 'B',
...     'state': 'open', 'user': {'login': 'u'}, 'updated_at': '2026-01-01T00:00:00Z',
...     'html_url': 'u', 'comments_data': []}).startswith('---')

hubcap.snapshot.snapshot_github(targets, *, store='github_snapshot', state=None, client=None, render=<function render_markdown>, kinds=('issues', 'pulls', 'discussions'), full=False)[source]#

Snapshot every repo of the given orgs ("org") or repos ("org/name").

Parameters:

  • store (MutableMapping | str) – a MutableMapping[str, str] or a folder path (default folder github_snapshot). Keys are <repo>/<kind>/<number>.md plus raw/<repo>/<kind>/<number>.json, index.jsonl and raw.jsonl.

  • state (Optional[MutableMapping]) – where the per-repo updated_at marks live; defaults to a .state.json entry inside store, so the folder is self-contained.

  • full (bool) – ignore the marks and refetch everything.

Return type:

dict[str, int]

Returns:

counts of items written per kind.

The state mark is advanced only after a repo’s items were all written, so a crash re-fetches (idempotently overwriting) rather than skipping.
